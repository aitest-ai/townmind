# 居民與群體（townmind）規格

> **方向更新**：玩法已改為動物森友會式的小鎮（玩家是住民、沒有失敗狀態）。後續工作順序與分工以 **`GAMEPLAY.md`** 為準；本文件的架構與資料格式仍然有效，但下面的 P1～P4 階段清單以 GAMEPLAY.md 的工作包（WP1～WP8）取代。

## 一句話
五位有個性的 AI「居民」當大腦，二十多個無名「小人」當身體；玩家不能直接操控，只能發公告、丟資源、改環境，間接影響居民的想法。

## 為什麼是這個組合
- **居民（大腦）**：少數有名字、性格、目標、記憶的角色，負責高層決策與社交。這裡才用 AI，而且只在關鍵時刻呼叫。
- **群體（身體）**：大量無名小人，用普通規則執行搬運、採集、蓋房，不花任何 AI 費用。
- 「間接指揮」是這套機制的賣點：玩家影響居民，居民指揮群體。換題材（牧場、太空站、校園）只要換資料與畫面，底座不動。

## 架構三層
```
玩家介入（公告／空投）
      │ 寫入居民記憶、觸發提早決策
      ▼
AI 決策層  src/brain.js  ←→  /api/decide（Vercel Function）→ LLM
  規則腦 mockDecide（免費、離線） / AI 腦 llmDecide（可替換）
  輸出一律過 validate()：只能從允許清單選，數量夾在 1~10
      │ { say, action:{type:'assign', task, count} }
      ▼
世界模擬層  src/world.js（完全不用 AI）
  地圖、資源、小人狀態機、糧食消耗、心情、房屋
```
資料流原則：**世界永遠能自己跑**；AI 掛掉、沒額度、沒網路，居民自動退回規則腦，遊戲不中斷。

## 資料格式
**角色卡**（使用者唯一需要編輯的東西，見 `data/npcs.js`）
```
{ id, name, role, color,
  card: { personality, goal, catchphrase,
          bias: { gather_food, gather_wood, build, rest } } }   // bias 給規則腦用
```
**居民輸出**（AI 腦與規則腦共用）
```
{ say: "30字內心聲", action: { type:'assign', task:'gather_food|gather_wood|build|rest', count:1~10 } | { type:'wait' } }
```
**小鎮快照**（餵給居民的狀態）：見 `snapshot()`，含糧食、木材、心情、房屋、施工進度、各任務人數。

## 護欄（都已寫進程式）
1. 提示詞模板在 `src/prompt.js`，護欄規則寫死；使用者只填角色卡欄位，欄位長度有上限、控制字元會被濾掉。
2. 公告與角色卡一律當「資料」而非指令；模板明講無視要求忽略規則的內容。
3. AI 的輸出先過 `validate()`，亂填任務名會被當成 `wait`（已測試）。
4. 內容限定兒童適用。

## 畫面層：2D／3D 可切換（同一份世界資料）
```
world / npcs（遊戲狀態，唯一真相）
   ├─ src/render2d.js            2D 俯視圖
   └─ src/render3d/index.js      3D 場景（three.js，已放在 vendor/，不需安裝或 build）
         ├─ characters.js        角色統一介面 + 程式生成人形（暫代）
         └─ glb.js               GLB 角色轉接器（接 3dcodeverse-lab 資產工廠，尚未實測）
```
- 所有視圖實作同一個介面 `render(frameDt, simDt, speed)`，渲染層**不得修改遊戲狀態**。
- 座標：世界 (x, y) → 3D (x, z)，1 世界單位 = 0.1 公尺，倉庫為原點；人物用「玩具比例」放大，方便從高處看。
- **角色統一介面**：`{ object, play(clip), update(dt), setTint(hex), setCarry(kind) }`，動作名稱固定為 `Idle / Walk / Carry / Work / Pick / Rest`。
- 小人的動作由世界狀態推導（位移速度、`state`、`carry`），不是另外存一套，所以 2D／3D 永遠同步。
- 換成工廠角色只要在 `data/npcs.js` 的居民上加 `model: '/models/xxx.glb'`；載入失敗會自動退回程式生成角色並在 console 警告。
- 3D 失敗（裝置不支援 WebGL）會自動退回 2D，並在事件紀錄用白話說明。

## 目前底板已完成（已用瀏覽器實測）
- 3D 小鎮：地形、外圈森林、花、樹與灌木（會隨剩餘量縮小）、倉庫廣場（庫存會變成木材堆與糧食籃）、房屋蓋好時彈出、工地牆隨進度長高、緩慢移動的陽光與陰影、可旋轉／平移／縮放的相機。
- 3D 人物：群體小人依任務換衣服顏色，會走、搬運（手上有東西）、砍柴、彎腰採果、坐下休息；5 位居民各有帽子（草帽、安全帽、頭巾、貝雷帽等）、名牌與氣泡，名牌大小會隨鏡頭距離調整。
- 世界模擬：資源點會再生、小人採集／搬運／蓋房／休息、糧食消耗、心情、10 間房子上限。
- 5 位預設居民，規則腦可獨立運行；公告關鍵字會改變居民決策。
- 介入介面：發公告、空投糧食與木材、調速度、切換規則腦／AI 腦、即時編輯角色卡、事件紀錄。
- AI 腦沒有後台時自動退回規則腦，並在紀錄裡說明原因（已測試）。

## 尚未完成（交給 Code 的主要工作）
**P1 驗證好玩**（優先）
- **目標斷層**：蓋滿 10 間房子約只要 2 分鐘（8 倍速下更快），之後就沒有目標了。要設計中長期目標（新建築種類、人口成長、季節或事件、通關條件），這是現在最大的玩法缺口。
- 平衡調整：木材常見底，要決定這是「有張力」還是「太難」；居民之間互相搶人的抖動需不需要「協商」或冷卻。
- 讓居民的決策感覺更有個性：現在規則腦只靠 bias，可加入口頭禪、對事件的反應。
- 先在規則腦上把「間接指揮好不好玩」玩透，再接 AI。

**P2 接上真正的 AI 腦**
- `api/decide.js` 已寫但**未用真實金鑰測試**；要部署到 Vercel、設 `ANTHROPIC_API_KEY`、實測格式與延遲。
- 費用控制：只在事件或固定間隔呼叫、限制每場次數上限、考慮批次一次問多位居民、快取相似狀態。
- 防濫用：`/api/decide` 目前沒有速率限制與來源檢查，上線前一定要加。

**P3 記憶與後台**
- 記憶摘要：事件日誌定期壓縮成一兩句「人生摘要」，避免提示詞越長越貴。
- 角色卡持久化（存檔／多組存檔）、新增與刪除居民、匯入匯出。
- 孩子自訂角色卡時的內容過濾（欄位送出前先過一道檢查）。

**P3.5 高品質 3D 角色（走資產工廠）**
- 目前的角色是程式生成的暫代品，質感有限。正式角色請走 3dcodeverse-lab 的 Blender 5 → GLB 流程，需求見 `ASSET_REQUEST.md`。
- `src/render3d/glb.js` 已寫好但**沒用真實 GLB 測過**；第一個工廠角色到手時，要驗證動畫名稱對應、尺度、朝向（預期臉朝 +Z）、腳是否貼地。
- 群體小人數量上百時，每人一組骨架與多個 mesh 會吃力，屆時要改成 GPU instancing 或動畫貼圖（vertex animation texture）。

**P4 群體進階與換皮**
- 小人數量提升到上百、尋路避障、群體隊形。
- 抽出「題材資料層」（任務名、資源、顏色、文案、居民卡），做成可換皮的設定檔，方便做牧場、太空站等版本。

## 怎麼跑
```
cd townmind && python3 -m http.server 8123
# 開 http://localhost:8123
```
純 ES Module，不需要 build。three.js（r187）已複製在 `vendor/three/`（含授權檔），用 import map 載入。必須用本機伺服器開，直接點 `index.html` 因瀏覽器限制無法載入模組。
